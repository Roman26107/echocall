# EchoCall

Аудио- и видеозвонки из Telegram с браузерным интерфейсом на Jitsi Meet.
Бот управляет пользователями и жизненным циклом звонка, а браузер подключается
к конференции без установки отдельного приложения.

## Возможности

- Регистрация, уникальный ник и выбор часового пояса.
- Контакты, история звонков, чёрный список и персональные настройки.
- Приглашения в Telegram и доступ к звонку по индивидуальной ссылке.
- Управление микрофоном и камерой, смена камеры на мобильных устройствах.
- Координация вкладок, чтобы несколько окон не захватывали устройства одновременно.
- Светлая и тёмная темы, мобильная панель управления и локальное превью видео.
- Административное меню: статистика, диагностика сервисов и запуск резервного копирования.
- Зашифрованные резервные копии PostgreSQL и проверка восстановления.

## Архитектура

В простом варианте бот и веб-приложение работают с общей базой данных:

```text
Telegram ── bot ────────── PostgreSQL
              │                │
              └─ ссылка ── Flask web ── браузер ── Jitsi Meet / TURN
```

Для раздельного размещения предусмотрены две роли:

```text
Bot / Telegram Gateway                 Web / Internal API
          │                                      │
          ├──── HTTPS + bearer ───────────────────┤
          │                                      ├── PostgreSQL
          │                                      └── Redis
          │
       Telegram API                   Браузер ── Jitsi / TURN
```

Бот в remote-режиме не получает доступ к базе. Веб-сервис использует Telegram
Gateway и не нуждается в токене бота. Внутреннее API ограничено явным списком
операций; изменяющие запросы используют ключи идемпотентности. Медиатрафик
обрабатывает Jitsi, а не Flask.

## Быстрый запуск

Нужны Docker с Compose, собственный Telegram-бот и доступный экземпляр Jitsi Meet.

```bash
cp .env.example .env
```

Заполните в `.env`:

- `BOT_TOKEN` и `BOT_USERNAME` — данные вашего бота;
- `ADMIN` — ваш Telegram ID, если нужно административное меню;
- `POSTGRES_PASSWORD` — собственный пароль, не значение из примера;
- `DOMAIN` — адрес веб-приложения, доступный участникам звонка;
- `JITSI_DOMAIN` — домен вашего Jitsi Meet, без схемы `https://`.

```bash
docker compose up -d --build
docker compose ps
curl --fail http://localhost/health/ready
```

Миграции запускаются отдельным сервисом перед стартом приложения. Откройте своего
бота в Telegram и отправьте `/start`.

Для звонков с другого устройства нужен доступный HTTPS-адрес приложения и
корректно настроенный Jitsi/TURN. `localhost` подходит для локальной проверки,
но не является адресом для приглашения другого участника. Общедоступный сервер
Jitsi в примере не является гарантированным backend для вашей установки.

Для локальной разработки без Docker зависимости устанавливаются так:

```bash
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
alembic upgrade head
python -m web.app
# В другом терминале с тем же окружением:
python -m bot.app
```

При таком запуске задайте `DATABASE_URL` самостоятельно либо используйте SQLite
по умолчанию. SQLite удобен для разработки и тестов; Compose использует PostgreSQL.

## Тесты

Python-тесты используют стандартный `unittest`; отдельная установка pytest не нужна.
Команды выполняются из корня проекта после установки зависимостей:

```bash
python -m unittest discover -s tests -v
node --test tests/call_runtime.test.js tests/call_tab_coordinator.test.js tests/embedded_self_view.test.js
```

Требуются Python 3.12+ и Node.js 22+. Покрыты health endpoints, внутреннее API,
gateway, отчёты об ошибках, мониторинг, backup-скрипты, жизненный цикл звонка,
безопасность capability-ссылок, миграции и координация вкладок.

CI проверяет Python 3.12/3.13, JavaScript runtime, синтаксис shell и три Compose-
конфигурации. Отдельная задача запускает миграции и API с временными PostgreSQL/Redis,
строит Docker-образ и проверяет непривилегированного пользователя. Ещё одна задача
запускает `pip-audit`; доступа к рабочим серверам у CI нет.
Интеграционный тест `test_service_integration.py` локально пропускается, если
`ECHOCALL_INTEGRATION_TESTS=1` не задан. Не включайте его на базе с реальными данными.

## Надёжность и модель доступа

- Участник получает индивидуальную случайную capability-ссылку. Её владелец может
  действовать от имени этого участника; ссылка не заменяет подтверждение личности.
- Jitsi-комната имеет отдельное случайное имя, а не последовательный ID из БД.
- Веб-ответы со ссылками не кешируются; referrer не передаётся внешним ресурсам.
  CSP ограничивает скрипты и iframe, access logs не записывают URL звонков.
- Повторное открытие не переписывает время первого подключения. Временный `503`
  при проверке статуса не разрывает разговор; ошибка Telegram не отменяет уже
  сохранённое подключение или завершение.
- PostgreSQL сериализует одновременные приглашения блокировками строк: занятого
  пользователя нельзя включить во второй звонок. SQLite не даёт такой гарантии
  параллельности и остаётся вариантом для локальной разработки.
- Внутренние HTTPS-клиенты не следуют перенаправлениям и ограничивают размер ответа.
  URL сервисов и таймауты проверяются при старте.
- Remote-мутации требуют Redis: повтор ключа с тем же запросом возвращает результат,
  с другим — `409`. При неопределённом результате commit сохраняется блокировка
  на 24 часа; это защита от повторного действия, а не обещание exactly-once.

Новая миграция назначает имена уже существующим комнатам. Обновляйте приложение
только после миграции и вне активных звонков: старые вкладки используют прежние имена.
Проверки и ограничения описаны в [SECURITY.md](SECURITY.md).

## Структура

```text
bot/                 Telegram handlers, клавиатуры и FSM
web/                 Flask, HTML-шаблоны и браузерный интерфейс звонка
gateway/             Изолированный шлюз Telegram API
shared/              Модели, сервисный слой, аналитика и внутреннее API
migrations/          Миграции Alembic
docker/              Entrypoint, Nginx и опциональный Jitsi UI overlay
scripts/             Развёртывание и резервное копирование
tests/               Python- и JavaScript-тесты
```

Это самостоятельная портфолио-версия: домены и адреса в конфигурациях — примеры,
данные пользователей и доступ к работающей инфраструктуре не включены.
Jitsi, TURN, TLS-сертификаты и облачные хранилища настраиваются отдельно.
Опциональный Jitsi overlay зависит от совместимой версии Jitsi; приватный базовый
образ из исходной установки не поставляется. Восстановление медиа после блокировки
iOS покрыто runtime-тестами, но требует проверки на реальных устройствах: браузер
и ОС могут ограничивать захват звука в фоне.

Перед обслуживанием реальных пользователей необходимо подготовить собственные
правила работы с персональными данными и проверить конфигурацию безопасности.
