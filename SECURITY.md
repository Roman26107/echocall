# Безопасность

## Конфигурация

- Храните токен бота, пароли БД, bearer-токены и backup-ключи вне Git.
- Файлы `.env*.example` содержат только образцы. Для установки создайте локальные
  env-файлы и замените все демонстрационные значения.
- Не включайте в публикацию базы, дампы, логи, ключи SSH, TLS-ключи, OAuth-файлы
  или ссылки на реальные звонки: ссылки могут давать доступ к конференции.
- `.gitignore` и `.dockerignore` исключают локальные данные, но не заменяют проверку
  содержимого перед коммитом и сборкой.
- Используйте отдельные секреты для Internal API и Telegram Gateway. Ограничивайте
  доступ к этим сервисам на уровне reverse proxy и сети.
- PostgreSQL и Redis в раздельной конфигурации находятся во внутренней сети.
- Не публикуйте Docker socket. Backup-trigger принимает ограниченный набор
  systemd-команд через локальный Unix socket.

## Эксплуатация

Используйте HTTPS для удалённого доступа. Настройте сертификаты, собственный Jitsi
и TURN, сетевые ограничения, обновления зависимостей и мониторинг. Не включайте
debug-режим для публичной установки. Простой Compose предназначен для разработки
и первоначального запуска; разделение секретов по сервисам реализовано в
конфигурациях `rf` и `foreign`.

### Ссылки и медиасервер

Индивидуальная ссылка — bearer capability: любой, кто её получил, действует от
имени участника. Не пересылайте её, не добавляйте в аналитику и не включайте в логи.
Штатные access logs Nginx/Gunicorn пишут метод, статус и время без URL/referrer;
проверьте отдельно логи балансировщика, CDN, error logs, APM и браузерную историю.

Случайное 192-битное имя комнаты мешает угадыванию, но не заменяет авторизацию Jitsi.
Авторизованный участник видит имя комнаты в браузере и может его передать.
EchoCall проверяет жизненный цикл в приложении; прямой вход на Jitsi или сохранённое
имя комнаты не отзываются самим Flask. Для строгого контроля доступа нужны собственная
настройка Jitsi (например, JWT/secure domain), срок действия допуска и проверка
завершения на медиасервере. Такая интеграция в этой версии не реализована.

Веб-приложение выставляет `no-store`, `Referrer-Policy: no-referrer`, CSP с nonce,
запрет embedding и `nosniff`. Эти меры не защищают от расширений браузера,
вредоносного клиента или утечки ссылки пользователем. Не включайте debug публично.

### Сервисные запросы и идемпотентность

Internal API и Telegram Gateway URL должны использовать HTTPS; credentials внутри
URL запрещены. Редиректы не выполняются, JSON-ответ ограничен 2 MiB. Не отключайте
проверку TLS сертификата. Internal API credential даёт доступ ко всему allowlist —
это доверенный сервисный credential, а не токен конечного пользователя.

Redis обязателен для remote-мутаций. Ключи сохраняются 24 часа: повтор идентичного
payload возвращает кеш, другой payload — конфликт. Успешный commit и запись в Redis
не являются общей транзакцией. После сбоя записи результата или неопределённого
commit остаётся pending; до повторного действия проверьте БД вручную. Потеря Redis,
истечение TTL и новый ключ не гарантируют exactly-once. Вызовы внешних сервисов,
например backup-trigger, также не откатываются SQL-транзакцией.

### Обновления

Dependabot проверяет pip, Dockerfile и GitHub Actions. CI запускает `pip-audit` и
изолированные тесты PostgreSQL/Redis. Чистый аудит означает отсутствие известных
на момент проверки записей в выбранной базе уязвимостей, а не гарантию безопасности.
Полные версии транзитивных зависимостей пока не фиксируются lock-файлом.

Резервные копии содержат персональные данные. Храните их зашифрованными,
ограничивайте доступ, проверяйте восстановление и держите recovery-пароль отдельно.

## Если секрет попал в Git

Сначала отзовите или замените его у провайдера. Удаление строки из текущего файла
не удаляет её из коммитов, тегов, форков, логов CI или уже скачанных копий.
После ротации отдельно очищайте историю и проверяйте связанные артефакты.

## Сообщения об уязвимостях

Не размещайте действующие токены или персональные данные в публичных issues.
Используйте приватный канал владельца репозитория или Private vulnerability
reporting, если владелец его включил. Для воспроизведения используйте тестовые
учётные записи и обезличенные данные.
