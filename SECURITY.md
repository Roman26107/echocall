# Безопасность

## Конфигурация

- Храните токен бота, пароли БД, bearer-токены и backup-ключи вне Git.
- Файлы `.env*.example` содержат только образцы. Для установки создайте локальные
  env-файлы и замените все демонстрационные значения.
- Не включайте в публикацию базы, дампы, логи, ключи SSH, TLS-ключи, OAuth-файлы
  или ссылки на реальные звонки: ссылки могут давать доступ к конференции.
- `.gitignore` и `.dockerignore` исключают локальные данные, но не заменяют проверку
  содержимого перед коммитом и сборкой.
- Используйте отдельные секреты для Internal API и Telegram Gateway. Ограничивайте
  доступ к этим сервисам на уровне reverse proxy и сети.
- PostgreSQL и Redis в раздельной конфигурации находятся во внутренней сети.
- Не публикуйте Docker socket. Backup-trigger принимает ограниченный набор
  systemd-команд через локальный Unix socket.

## Эксплуатация

Используйте HTTPS для удалённого доступа. Настройте сертификаты, собственный Jitsi
и TURN, сетевые ограничения, обновления зависимостей и мониторинг. Не включайте
debug-режим для публичной установки. Простой Compose предназначен для разработки
и первоначального запуска; разделение секретов по сервисам реализовано в
конфигурациях `rf` и `foreign`.

Резервные копии содержат персональные данные. Храните их зашифрованными,
ограничивайте доступ, проверяйте восстановление и держите recovery-пароль отдельно.

## Если секрет попал в Git

Сначала отзовите или замените его у провайдера. Удаление строки из текущего файла
не удаляет её из коммитов, тегов, форков, логов CI или уже скачанных копий.
После ротации отдельно очищайте историю и проверяйте связанные артефакты.

## Сообщения об уязвимостях

Не размещайте действующие токены или персональные данные в публичных issues.
Используйте приватный канал владельца репозитория или Private vulnerability
reporting, если владелец его включил. Для воспроизведения используйте тестовые
учётные записи и обезличенные данные.
